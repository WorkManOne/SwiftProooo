# SwiftProf

Обфускатор идентификаторов Swift на базе SwiftSyntax. По набору исходных модулей
он переименовывает объявления (типы, члены, функции, параметры, кейсы enum) и все
места их использования в непрозрачные имена, сохраняя сборку зелёной.

Два продукта:

- **`swiftprof`**: консольная утилита.
- **`SwiftProfCore`**: библиотека со всем движком (резолвер, проходы, отчёты),
  чтобы логику можно было покрывать юнит-тестами независимо от CLI.

По умолчанию SwiftProf разрешает имена **синтаксически** (индекс компилятора не
нужен), поэтому он самодостаточен и не требует заранее собранного индекса. Для
дополнительной точности на больших проектах есть опциональный слой USR/индекса
(см. [Слой индекса](#слой-индекса-опционально)).

## Быстрая обфускация

Для тех, кто не знаком с проектом, есть готовый путь в два шага (нужен Mac с
Xcode, см. [Требования](#требования)):

1. Файл [`swiftprof.yaml`](swiftprof.yaml) копируется в корень проекта под тем же
   именем `swiftprof.yaml`. В нём заполняются две вещи: пути к модулям (`module`) и
   имя Xcode-проекта для подключения SPM-пакетов (`auto-spm`). Если SPM-пакетов в
   проекте нет, строка `auto-spm` не нужна. Остальные настройки уже проставлены.
2. Из каталога SwiftProf скрипт запускается с путём к проекту:

```bash
./obfuscate.sh /путь/к/Проекту
```

Скрипт сам собирает инструмент (release), кладёт бинарник в видимую папку
`swiftprof/` рядом со скриптом (а не в скрытую `.build`) и обфусцирует проект.
Руками в yaml нужно заполнить только пути к модулям и имя Xcode-проекта
(`auto-spm`): инструмент должен знать, какие папки переписывать и откуда брать
SPM-пакеты, а это индивидуально для проекта.

Обфускация переписывает исходники **на месте**, поэтому её делают на копии
проекта или под git, а дерево возвращают после сборки (`git restore .`).

После обфускации имена в логах ошибок приложения становятся непрозрачными. Чтобы
читать такой лог с оригинальными именами, есть парный скрипт `./deobfuscate.sh`
(см. [Деобфускация логов ошибок](#деобфускация-логов-ошибок)).

## Требования

- macOS 13 или новее.
- Тулчейн Swift 6 (Xcode или Command Line Tools).
- Разбор SDK и опциональный слой индекса во время работы обращаются к `xcrun`,
  поэтому на машине, которая реально обфусцирует iOS-проект, должен быть Xcode.

## Сборка

```bash
swift build                 # отладочная сборка
swift build -c release      # release-сборка (для боевых прогонов)
```

Release-бинарник появляется по пути `.build/release/swiftprof`. Он собирается с
ad-hoc подписью и переносим на любой Mac с совместимым тулчейном. Локально
собранный бинарник не помечается карантином Gatekeeper.

## Тесты

```bash
swift test                          # полный набор
swift test --filter PatternTests    # основной end-to-end набор по разрешению имён
swift test --filter <ИмяТеста>      # один тест
```

`PatternTests` (`Tests/SwiftProfCoreTests/PatternTests.swift`) это регрессионный
набор: на каждый исправленный баг разрешения имён здесь есть тест.

## Запуск

Обычный путь это файл **`swiftprof.yaml`** рядом с проектом. Он автоматически
подхватывается из текущего каталога, поэтому обфускация это одна команда:

```bash
cd /путь/к/Проекту               # каталог, где лежит swiftprof.yaml
/путь/к/SwiftProf/.build/release/swiftprof
```

Конфиг можно указать и явно либо задать всё флагами:

```bash
# явный конфиг
swiftprof --config /путь/к/Проекту/swiftprof.yaml

# чистый CLI, без файла конфигурации
swift run -c release swiftprof \
  --module App:./Tests/PullTheTicket/PullTheTicket \
  --output ./out --debug-names --no-sdk-introspect
```

Инструмент **переписывает исходники записываемых таргетов на месте** (если не
задан `--dry-run`). Его запускают на одноразовой копии проекта или под git,
чтобы вернуть дерево после сборки. В каталог вывода (по умолчанию `./out`)
пишутся `ConversionMap.json` и `CoverageReport.txt`, а при `--explain` ещё и
отчёт решений.

### Минимальный `swiftprof.yaml`

```yaml
# записываемые таргеты, их исходники переписываются, формат имя:путь
module:
  - App:./App/Sources/App
  - Ext1:./App/Sources/Ext1

# SPM-пакеты проекта, только для чтения (нужен собранный DerivedData);
# не нужна, если SPM-пакетов в проекте нет
auto-spm: ИмяXcodeПроекта

# виды имён для обфускации
kinds:
  - class
  - struct
  - enum
  - protocol
  - typealias
  - associatedtype
  - method
  - function

explain: true    # отчёт решений (Decisions.txt) в каталоге вывода
```

Контракт конфига: **ключ = имя флага** (kebab-case, без `--`); флаги со списком
значений становятся YAML-списками; `module`/`readonly` это списки строк
`имя:путь`. Приоритет по каждому полю: **CLI > конфиг > встроенный дефолт**.
Относительные пути внутри файла считаются от каталога самого файла. Неизвестный
ключ верхнего уровня это жёсткая ошибка с подсказкой (fail-closed).

Полный конфиг со всеми ключами и комментариями лежит в
[`swiftprof.example.yaml`](swiftprof.example.yaml).

### Ключевые флаги

Полный список в [`Sources/swiftprof/main.swift`](Sources/swiftprof/main.swift).
Те, что задают обычный прогон:

- `--module имя:путь`: записываемый таргет (повторяемый). `--readonly имя:путь`:
  модуль только с объявлениями (например SPM-пакет), файлы не переписываются.
- `--kinds a,b,...`: обфусцировать только эти виды имён. Ими же бисекцией ищут,
  какой вид ломает сборку.
- `--ignore-names` / `--ignore-files` / `--ignore-targets`: списки пропуска для
  имён, завязанных на строки (Info.plist, сториборды), генерённых файлов и таргетов.
- `--auto-spm <ИмяXcodeПроекта>`: добавить SPM-пакеты из DerivedData как
  read-only модули (нужен уже собранный проект).
- `--objc-protection strict|relaxed|off`: насколько перестраховываться вокруг
  имён, видимых рантайму Objective-C. `strict` (по умолчанию) самый безопасный и
  даёт наименьшее покрытие; `off` не для Core Data и сторибордов.
- `--explain`: отчёт решений (`Decisions.txt`, `decisions.json`, а также
  обезличенный `Decisions-anon.txt` с легендой `Decisions-files.txt`).
- `--dry-run`: только отчёты, файлы не переписывать.
- `--debug-names`: короткие читаемые имена (`T0`/`m0`/`p0`) для инспекции, не
  для боевого прогона.

## Деобфускация логов ошибок

До обфускации имена в логах ошибок читаемые, а после обфускации те же ошибки и вылеты
приходят с непрозрачными именами. Поэтому, если потребуется разобрать ошибки в логах полученные удаленно, подкоманда `swiftprof deobfuscate` читает
`ConversionMap.json` (карту `оригинал -> обфусцированное`, которую пишет обфускация)
в **обратную** сторону и возвращает оригинальные имена: непрозрачное
`Kr9mPq2wLb7xTn4vZc1sJd6hFg8yAe3o` в логе снова читается как `UserService`.

Проще всего через парный скрипт (карта берётся из `<проект>/out/ConversionMap.json`):

```bash
pbpaste | ./deobfuscate.sh /путь/к/Проекту | pbcopy   # из буфера обмена (macOS)
./deobfuscate.sh /путь/к/Проекту error.txt            # из файла
xcodebuild ... 2>&1 | ./deobfuscate.sh /путь/к/Проекту # весь лог сборки
```

Тот же результат напрямую через бинарник:

```bash
swiftprof deobfuscate --map ./out/ConversionMap.json error.txt
```

- `--map <путь>` задаёт путь к `ConversionMap.json` (по умолчанию
  `./out/ConversionMap.json`), его можно указать несколько раз для мульти-модульных
  прогонов.
- `-o <файл>` пишет результат в файл вместо вывода на экран.
- `--replace` подставляет оригинал вместо обфусцированного имени; так по умолчанию
  для боевых имён из 32 символов. `--annotate` оставляет обфусцированное имя и
  дописывает оригинал рядом (`p0` становится `p0⟨→save⟩`); так по умолчанию для
  коротких отладочных имён (`T0`, `m0`, `p0`), которые могут совпасть с обычным
  словом в логе. `--strict` вовсе отказывается работать с картой коротких отладочных
  имён.

Инструмент подставляет читаемые имена в тексте лога. А в свёрнутых именах вида
`$s3App11UserServiceC4saveyyF`, которые Swift пишет внутри вылетов, обфусцированное
имя закодировано, а не лежит текстом, поэтому такие имена инструмент не разворачивает.

## Как это работает

`Pipeline.run()` (`Sources/SwiftProfCore/Pipeline.swift`) это двухфазный
многопроходный движок над SwiftSyntax. Первая фаза регистрирует каждое объявление
в `SymbolTable` и строит дерево областей видимости, затем серия проходов
разрешает владельцев расширений, объединяет области, протягивает видимость через
протоколы и суперклассы, выводит типы, помечает защищённые имена, планирует
переименования и связывает свидетелей протоколов и переопределения. Вторая фаза
(`ResolutionPass`) вручную воспроизводит разрешение имён Swift, разрешает каждое
использование в символ и выдаёт правку. Финальный `RollbackPass` откатывает любое
переименование, чьё оригинальное имя ещё уцелело в выводе: это и есть страховка,
которая держит сборку зелёной.

Основная сложность это разрешение имён: выбрать правильный символ среди
одноимённых кандидатов между таргетами, областями видимости и видами. Инварианты,
которые держат это корректным, описаны в комментариях к коду резолвера
(`Resolve/`, `Symbols/`): прочитайте их перед правкой кода разрешения имён.

### Слой индекса (опционально)

Флаг `--index-store-path <каталог>` включает слой ground-truth на USR: он
использует индекс компилятора, чтобы различать одноимённые символы между таргетами
и валидировать/выдавать переименования использований. Нужен заранее собранный
индекс, слой fail-closed (отсутствующий или устаревший индекс прерывает работу, а
не гадает). Сам путь это включатель: не указали его, и инструмент это чистый
синтаксический режим, байт-в-байт тот же. C-шим над `libIndexStore` грузится через
dlopen во время работы, поэтому бинарник остаётся переносимым и запускается на
машинах без Xcode; тулчейн нужен только для фактической передачи пути.

## Статус и ограничения

- SwiftProf это синтаксический обфускатор с реальным потолком точности на больших
  проектах, где много одноимённых символов между таргетами. Опциональный слой
  индекса это гибридный ответ для таких случаев.
- Проверенная конфигурация, дающая зелёную сборку, обфусцирует **типы и
  вызываемые** (class, struct, enum, protocol, typealias, associatedtype, method,
  function). Виды `property`, `enumCase` и `parameter` в этой конфигурации пока не
  включены; не добавляйте их без проверки сборки на вашем проекте.
- `RollbackPass` ловит *пропущенные* использования (оригинальное имя уцелело), но
  не ловит *неправильное* переименование (объявление и использование переименованы
  в несогласованные имена); последнее предотвращается корректным разрешением имён
  заранее, поэтому резолвер учитывает сигнатуры и модули.

## Раскладка репозитория

```
Sources/
  swiftprof/            CLI (разбор аргументов, обвязка)
  SwiftProfCore/        движок
    Passes/             проходы пайплайна (объявления, связывание свидетелей/override, откат, ...)
    Resolve/            резолвер имён и его помощники
    Symbols/            SymbolTable, области видимости, кадры биндингов
    Protection/         правила защиты имён (@objc, Codable, property wrappers, ...)
    Reporting/          отчёты покрытия и решений
    IndexStore/         опциональный слой USR/индекса
    SDK/                реестр stdlib/SDK
    Project/            поиск SPM, спецификации модулей
  CIndexStore/          C-шим над libIndexStore (только типы, dlopen во время работы)
Tests/
  SwiftProfCoreTests/   PatternTests + юнит-тесты
  IceTrays/, IceTrays1/, PullTheTicket/   примеры приложений для end-to-end тестов
```
